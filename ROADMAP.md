# From white paper to standard

Status: proposed sequence for community discussion. Dates and owners will be assigned through public issues.

| Phase | Work | Evidence needed to advance |
| --- | --- | --- |
| 1. Community formation | Publish the paper; collect use cases; refine the contribution process and charter | Public issue backlog, named editors, and founding-policy decisions |
| 2. Requirements | Define scope, terminology, interoperability needs, and exclusions | Reviewed use cases mapped to specific requirements |
| 3. Information model | Specify concepts, relationships, identifiers, revisions, and review semantics | Worked examples and documented decisions |
| 4. Experimental binding | Develop an initial serialization and validation approach | Examples plus positive and negative fixtures |
| 5. Interoperability | Exercise interchange between independent implementations | Published results, limitations, and resolved incompatibilities |
| 6. Candidate review | Publish a versioned candidate and solicit broad review | Comment dispositions, conformance evidence, and an adopted decision charter |

## First discussion topics

These are suggested questions, not accepted requirements:

- How should reusable plans, individual executions, and resulting decisions relate?
- How should revisions and references remain stable as participants edit a reasoning artifact?
- Which changes invalidate an earlier review or approval?
- What can a structural validator establish, and what still requires domain judgment?
- How should consumers handle unsupported extensions or inaccessible evidence?
- What constitutes equivalent meaning when exchanging an artifact between tools?

Use the [proposal format](CONTRIBUTING.md) to develop any topic. Link each accepted requirement to its decision record and eventual acceptance evidence.
